# 目录、路由、策略与价格作用域分离

Status: accepted

上游模型同步、模型路由、上游承接策略和价格同步都涉及“看起来相似但语义不同”的模型名。如果把上游 `/v1/models` 的发现结果直接当作能力，把路由规则直接指向上游模型名，或让第三方价格直接覆盖全局价格，就会绕过全局模型、下游 Key 权限、候选能力和人工审核边界。我们决定把上游模型目录、全局 Model、上游模型能力、模型名称路由、上游模型策略和价格档案保持为独立对象：目录同步只产生发现事实；显式导入或绑定才产生能力；路由只解析到全局 Model；黑名单优先于白名单并作用于全局 Model ID；价格使用全局默认加上游级覆盖，第三方报价先形成差异预览再应用。这个边界牺牲了一步自动化导入，但避免供应商目录变化、模糊匹配或价格源波动未经审核直接改变生产流量和费用归因。

## Considered Options

- 将目录同步结果自动创建并启用上游能力：拒绝，因为供应商目录是外部输入，不能直接成为生产路由授权。
- 用一张“上游模型”表同时承载发现、公开名称、路由和价格：拒绝，因为无法区分观察到、允许承接和对外暴露三种状态。
- 让名称路由直接指向上游模型字符串：拒绝，因为会绕过全局模型权限、能力关系和统一计费。
- 只保留全局价格：拒绝，因为同一全局模型在不同上游的实际成本可能不同，费用归因会失真。
- 允许任意 URL 作为第三方价格源：拒绝，因为会扩大 SSRF、解析不稳定和误覆盖风险。

## Consequences

- 控制面需要保存目录同步批次、策略、路由、价格档案和报价审核状态，管理界面也需要更多预览和冲突反馈。
- 核心配置需要增加路由和策略能力协商；不支持这些语义的旧核心不能接收依赖它们的流量。
- 用量事件需要保留 requested model、resolved model、upstream model 和 price revision 等归因信息。
- 目录和价格源失败时可以保留上一次有效事实，避免外部依赖故障清空生产配置。
