# 目录同步标记与模型接受、删除分离

Status: accepted

价格源目录的开关同时被读成“是否加入全局模型”和“是否启用该模型”，导致关闭开关时只能靠删除全局模型来表达，删除又会连带丢失价格修订与上游绑定。我们决定把三件事拆开：目录行只记录**同步标记**（所有者希望该源模型保持为全局模型），打开时确保全局模型存在、关闭时只清标记；全局模型自身的**接受状态**（`enabled`）由全局模型页的开关控制；**删除**只发生在全局模型页，删除后目录行因为目标模型不存在而显示为关闭，刷新不会按标记重建。目录同步标记按「来源 + 来源模型」持久化，显示的开关状态是“标记已设置且目标全局模型存在”。

## Considered Options

- 开关直接表示全局模型是否存在：拒绝，因为关闭不删除时模型仍在，开关会立即弹回打开，无法表达“停止同步”。
- 关闭开关即删除全局模型：拒绝，因为删除不可逆地丢弃价格修订、上游绑定和接受状态，且被引用的模型无法删除。
- 标记与存在性都不保存，只靠目录快照判断：拒绝，因为无法区分“用户从未开启”和“开启后又在别处删除”。
- 在删除全局模型时回写清除同步标记：拒绝，因为形成双写；显示层用“标记 && 存在”推导即可得到同一结果。

## Consequences

- 目录、全局模型和接受状态各自有独立的写路径，审计事实也分别归属。
- 目录开关的显示依赖两处事实（标记、模型存在性），读取目录时需要联查全局模型。
- 删除全局模型不会改变任何目录行数据；重新加入必须由所有者再次打开开关。
